# 毒奶

## 调用方式与工具

- DeepSeek Harness：用户输入 `/du-nai` 即注入本技能全文；模型也可按 description 命中后用 `skill` 工具加载名称 `du-nai`。同一轮只走其中一条路径，不要重复加载。
- Codex：使用 `$du-nai`。
- `references/` 下的文件按本技能基目录解析相对路径，按章型按需读取，不要预先全量载入。
- 联网（仅热梗任务需要）：先用 `web_search` 检索；需要原始页面时用 `pwsh` 发 `Invoke-WebRequest` 或 `curl`；遇到 403、反爬或 JS 应用壳时改用 `browser-cdp` 技能（`/browser-cdp`）驱动 Chrome。
- 落盘：仅在用户明确要求时用 `write` / `edit` 工具写文件；正文默认直接输出在聊天框。

## 执行流程

1. 判断任务是正文、续写、改写、大纲、人物、设定还是风格分析。正文才执行完整章节流程；规划类任务保留相同的人物逻辑、能力因果和轻喜剧节拍。
2. 续写前读取最近两到三章或用户提供的全部有效上下文，在内部建立状态账本：时间地点、在场人物、当前目标、未解冲突、关系温度、伤势体力、能力等级、资源数量、秘密承诺和上一章钩子。不要把账本展示给用户，除非用户明确要求。
3. 写作前读取 `references/style-profile.md`。先读“全语料校准”“叙事视角”“语言节奏”“主角吐槽机制”，再按主章型读取对应章节。不要把参考画像逐条写进正文。
4. 只在用户明确要求近期热梗或当下网感时读取 `references/meme-workflow.md`。默认优先回收前文已有称呼、误会和人物梗，不临时追逐新梗。
5. 用一句话确定本章章核：谁想完成什么，什么压力阻止他，主角准备怎样处理，章末产生什么可见变化。一章只设一个主章核，可带一条关系或成长副线。
6. 直接进入场景。按“落地 -> 异常 -> 判断 -> 行动 -> 结果”推进；设定解释使用“正式规则 -> 主角通俗翻译 -> 对当前利益或危险的影响 -> 立即选择”的循环。
7. 初稿后先做连续性与因果复核，再做节奏、对白和去 AI 味复核。任何笑点、升级、反转或胜负都必须能在前文找到触发条件。
8. 正文默认直接输出在聊天框中，不附创作说明。只有用户明确要求写入文件时才用 `write` / `edit` 工具创建或修改文件。

## 章型选择

- 日常、误会、温情：读取“日常误会写法”“情绪特色”“叙述动作与关系”。
- 训练、升级、能力实验：读取“训练写法”“能力实验写法”“设定展开”。
- 异空间、狩猎、灰色现实：读取“长线狩猎写法”“灰色现实写法”“冷静指挥写法”。
- 战斗、赛事、公开考试：读取“战斗写法”“赛事与多屏现场”及对应模板。
- 校园过渡、组队、对手铺垫：读取“校园主线衔接”“人物塑造”“章节节拍与标题”。

## 核心声音

- 使用以主角为中心的弹性有限视角。每个场景只设一个认知锚点；允许在明确转场后短暂进入队友、对手或旁观者视角，不在同一段里来回读心。
- 让叙述、动作、观察和内心判断承担主要篇幅。对白负责命令、决定、关系变化和笑点收口，不负责把常识问答给读者听。
- 普通短对白与说话者动作、神态或主角反应放在同一段；只有短命令、关键揭示、连续问句中的重音和笑点落槌才单独成段。不要把整场对话排成一问一答的短行队列。
- 让主角先按现实生活、钱、游戏、考试、饭局或家庭经验理解陌生规则。他可以想歪、自我安慰和嘴硬，但要很快落回行动与利害判断。
- 让幽默从信息差、能力错用、身份反差、命名误解、现实制裁和结果反转中生长。不要按固定间隔插段子，也不要让所有角色共用主角的网感。
- 让正式设定和口语解释并存。先保证等级、技能、距离、消耗、成功率和限制说得清，再由主角给出一句带利益倾向的通俗判断。
- 让成长落在可核对的变化上：多撑一轮、少退一步、技能升一级、库存少一枚、队友重新分配位置。强能力同时带来星力、暴露、资格或资源成本。
- 让温情落在具体照料、资源分配、站位保护、等待和沉默后的选择上。说一句到位便停，不替人物总结主题。

## 节奏控制

- 主体使用短中段叙述，关键判断、问句、反应和结果才独立成短段。完整的观察、动作、结果优先合在一个约 20-60 字的段落里，不要把每个动作都另起一行。
- 完稿后执行一次“并段检查”：逐个查看不超过 12 字的段落，只保留问句阶梯、短命令、倒计时、认知翻转和结果爆点；普通动作、方位、人物名和解释句并入相邻段。约 1800-2500 字的章节通常控制在 70-110 个有效段落，短段不超过约三成；这是触发返修的上限，不是凑数配额。
- 可以用两到四个连续问句表现主角的认知失衡，随后必须由事实、动作或新判断回答。一次场景不要反复使用同一问句阶梯。
- 允许在转折点做两三拍短反复，放大危险或喜剧结果；区分有意反复与工整排比，后者应删。
- 压力越高，吐槽越短。潜行、死亡、亲情和关键决策处减少玩笑；危险解除后再用生活细节或延迟反应降温。
- 公开赛事和大型行动才使用主播、观众、裁判或监控人员等副视角。每次切镜补充规则、风险或舆论反差，完成作用后立即回到主线。
- 意外结果可以先呈现，再短暂回溯关键准备动作；只补完整一条因果链，不重播整场战斗。

## 原创边界

- 只模仿高层叙事机制，不复用参考文本中的原句、角色名、地名、技能名、章节标题、人物组合、专有设定或标志性桥段。
- 不把“？？？”“在线等”“稳如老狗”等表面词汇当成文风本体。优先复现贴近认知、利益换算、错位判断、行动反馈和关系反差。
- 涉及未成年角色时不写露骨性描写。暧昧调侃停在误会、口嗨、被打断或被制止的层面。
- 残酷场面服务人物认知和世界规则，不堆血腥奇观，不把搜刮尸体写成无代价的纯爽点。

## 交稿复核

- 状态账本是否连续：时间、位置、在场人物、伤势、技能、库存、积分和承诺能否与前文对上。
- 本章是否有明确目标、阻力、选择和可见结果，结尾是否承接下一步行动。
- 设定是否经过“规则、通俗翻译、现实影响、角色选择”，而不是脱离场景成段科普。
- 吐槽是否由当前信息或动作触发，并承担人物、信息或节奏功能。
- 问句和短段是否集中在真正的认知转折处，正文是否仍有足够完整的动作段落。
- 是否执行了并段检查；若普通动作仍被拆成连续单行，合并后再交稿。
- 对白是否符合角色口气，是否删掉寒暄、复述、百科问答和连续多人斗嘴。
- 战斗是否看得清站位、技能链、反制和代价；反常能力用法是否已经提前成立。
- 公开副视角是否必要，弹幕或观众是否避免同质化刷屏。
- 温情是否由动作落地，爽点是否由结果确认，残酷是否改变主角的判断。
- 是否删掉多余形容词、万能抒情、机械对照句、连续比喻和整齐排比。
