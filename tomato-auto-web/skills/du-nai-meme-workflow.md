# 近期网络热梗工作流

## 来源

优先访问：`https://gengbaike.cn/category-view-13.html`

该分类页按创建时间倒序展示词条，包含标题、创建时间、浏览量、摘要和详情页链接。把它当作热梗发现入口，不把用户编辑内容当作严谨事实来源。

## 检索

1. 每次用户明确要求“近期热梗”时重新访问第一页，不依赖长期记忆。
2. 若普通 HTTP 请求返回 `403`，改用 `browser-cdp` 技能（`/browser-cdp`）驱动 Chrome 读取渲染后的页面；用 `pwsh` 命令行请求时附带常见浏览器 User-Agent、中文语言头和站点 Referer。
3. 读取第一页最近的 10-20 个词条，优先考虑近 90 天创建且浏览量较高的条目；候选不足时放宽到 180 天。
4. 选出 3-5 个与本章人物、冲突或情绪匹配的候选，并打开详情页确认来源、含义、使用场景和语气。
5. 若站点不可访问，用 `web_search` 工具检索该站词条或站外转载；仍不可用时继续写作，不虚构“近期热梗”，并简短说明未能联网检索。

## 筛选

- 使用优先级：前文已成立的关系梗或称呼 > 当前场景自然产生的语义误读 > 近期网络热梗。前两类已经足够时，不再额外插新梗。
- 先查看续写状态账本，确认本章能否回收旧动作、旧误会、旧承诺或旧外号。回收时改变用途或情境，不原样复读。
- 优先选择读者不看注释也能领会的句式梗、反差梗、自嘲梗和吐槽梗。
- 优先选择能自然落在主角内心 OS、朋友斗嘴、战后吐槽、技能命名误会里的梗。
- 排除依赖视频画面、特殊配音或长篇背景才能成立的梗。
- 排除政治、灾难、真实人物争议、歧视、骚扰、露骨色情和恶意辱骂类梗。
- 避免只因创建时间新就采用；创建时间、浏览量、适配度三项一起判断。

## 融入正文

- 每 1500-2500 字最多放一个显眼热梗；可以有一个更轻的变体，但不要连续抛梗。
- 这个数量是上限，不是任务。没有适配梗时保持不用，场景自产笑点比新鲜度更重要。
- 优先改写梗的句式或语气，使其服从人物口吻和世界观，不整句照搬词条摘要或网络原话。
- 现代穿越者可在内心使用现实网络梗；本土角色只有在世界设定允许时才能说同类流行语。
- 古代、异世界或封闭场景中，去掉平台名、品牌名和现实人物名，保留反差结构或笑点逻辑。
- 梗必须承担至少一个作用：推进关系、缓和危险、暴露性格、形成误会、完成情绪转折。
- 不在正文里解释梗的来源。需要解释才能看懂时，换一个梗。
- 不让全员使用同一种网感。嘴贫主角可以多一点，冷面角色少说，严肃角色偶尔说一次才有反差。

## 时效与原创

- 把“近期”按写作当天向前 90 天理解；用户指定时间范围时以用户要求为准。
- 不保证梗网站的创建时间等于全网首发时间，只把它用于判断近期收录和当前传播度。
- 不复制词条正文，不照搬长台词，不复刻具体二创桥段；只提炼梗义、语气和适用场景。
- 同一个梗在连续三章内只使用一次，避免把短期网感写成固定口头禅。

## 交稿前检查

- 删除任何需要括号解释的梗。
- 删除会破坏年代、地域、人物身份或紧张气氛的梗。
- 检查梗是否抢走剧情重点；若读者只记得梗而忘了冲突，删掉或压轻。
- 确认正文即使读者没见过该梗，也能通过上下文读懂笑点。
