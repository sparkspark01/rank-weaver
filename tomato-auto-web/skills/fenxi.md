# 番茄榜单分析

## 调用方式与工具

- DeepSeek Harness：用户输入 `/fenxi` 即注入本技能全文；模型也可按 description 命中后用 `skill` 工具加载名称 `fenxi`。同一轮只走其中一条路径，不要重复加载。
- Codex：使用 `$fenxi`。
- 联网取数按以下顺序降级，不要跳过前一级直接猜数据：
  1. `web_search` 检索榜单页、书籍页、榜单转载与同站点公开入口；
  2. `pwsh` 直接请求页面或接口（`Invoke-WebRequest` / `curl`，附带常见浏览器 User-Agent、中文语言头和站点 Referer），用于拿原始 HTML 或 JSON；
  3. 页面返回 403、反爬、空白或只有 JS 应用壳时，改用 `browser-cdp` 技能（`/browser-cdp`）驱动 Chrome 读取渲染后的 DOM 或页面内数据接口。
- 逐本打开 `/page/{book_id}` 还原乱码工作量大时，可用 `subagent` 并行扇出（每本或每若干本一个子任务），再自行汇总；子代理的结论必须回到本报告的口径与格式，不要分散成多份报告。
- 数据只来自本次联网结果：不读本地缓存当榜单，不凭记忆补榜单；无法读取时在报告中写明缺口。

## 工作流

1. 必须联网获取最新榜单；优先访问 `https://fanqienovel.com/library/stat1/page_1?sort=hottes`：先用 `web_search` 定位该页，再用 `pwsh` 取原始 HTML；页面不可直读时走 `/browser-cdp`。
2. 只取“连载中”样本。若使用接口，优先请求 `https://fanqienovel.com/api/author/library/book_list/v0/`，常用参数为 `page_count=20&page_index=0&gender=-1&category_id=-1&creation_status=1&word_count=-1&book_type=-1&sort=0`；页面 `sort=hottes` 通常对应接口 `sort=0`，`creation_status=1` 通常对应连载中。
3. 记录抓取日期、榜单 URL、排序方式和数据可见性；若只能拿到部分信息，明确说明缺口。
4. 若页面只返回 JavaScript 应用壳、反爬、空白或无法直接读取榜单，先用 `/browser-cdp` 取渲染后的页面，再用 `web_search`、页面数据接口或同站点公开榜单入口交叉确认；不要凭记忆补榜单。
5. 只分析连载中榜单前二十名小说。为每本书提取：书名、作者、简介/标签、排名、可见热度指标、题材判断依据。不要把已完结作品纳入样本；若榜单混入已完结作品，剔除后顺延补足二十本。
6. 若 API 返回的书名、作者、简介或热度文字出现字体混淆乱码，逐本打开 `/page/{book_id}` 书籍页，从 `<title>`、meta description、JSON-LD、页面标签和作品简介中还原；仍无法还原时再用 `web_search` 交叉确认。书籍数量多时按上文用 `subagent` 并行还原。
7. 将前二十名按题材归类。若一本书混合多题材，标出主题材和副元素；最终输出“热门题材排名”，而不是固定只输出前五个题材。
8. 题材排名按综合热度计算：榜单名次权重、同题材作品数量、可见热度指标、标签重复度、简介核心冲突相似度。排名中说明每个题材的代表作品、占位数量和判断依据。
9. 对每个热门题材总结：题材名称、代表作品、主要剧情主线、开局钩子、升级/变强路径、关系线、反派或压力源、爽点机制、读者期待。
10. 最后给出市场观察和创作启发，但不要把观察写成确定预测；区分“榜单显示”和“推断”。

## 剧情匹配评估

当用户提供小说大致剧情、梗概、设定或开篇构思时：

1. 先判断当前对话中是否已有刚刚生成的连载中题材榜单；若没有，或榜单来源/日期不清楚，则先按“工作流”获取最新连载中前二十名并生成题材排名。
2. 从用户剧情中提取：主题材、副元素、主角初始困境、核心金手指或推进机制、长期目标、主要矛盾、情感/关系线、预期爽点。
3. 将用户剧情对照题材排名，判断它落在哪些热门题材上，是否命中榜单里的主流叙事主线和爽点机制。
4. 给出匹配等级：高匹配、中匹配、弱匹配、不匹配。说明理由，不要只给结论。
5. 若不匹配或只弱匹配，指出差距来自题材外壳、剧情主线、主角动机、升级机制、冲突强度、爽点密度、受众期待中的哪一项。
6. 给出可选调整建议：保留原创核心，补强与热门题材榜单相近的卖点；不要建议用户简单套壳或抄袭榜单作品。

## 参考榜单生成大纲

当用户提供小说大致剧情，并明确要求“参考番茄榜单/热门榜/题材榜单生成大纲”时：

1. 必须先执行“剧情匹配评估”，不要跳过题材对应性判断直接写大纲。
2. 将匹配等级解释为执行门槛：高匹配或中匹配视为“对应”；弱匹配、不匹配或关键信息不足视为“暂不对应”。
3. 若对应，选择题材排名中与用户剧情最接近的 1-3 个代表作品作为结构参照，只参考题材机制、主线节奏、爽点分布和读者期待，不复制书名、角色名、具体设定、桥段、台词或专有名词。
4. 若对应，先说明“对应的热门题材”和“可参考的榜单作品类型”，再生成原创大纲。大纲至少包含：一句话卖点、题材定位、主角设定、核心矛盾、金手指或推进机制、前三章开局、阶段主线、主要反派/压力源、爽点安排、阶段性钩子。
5. 若用户要长篇规划，按“开篇 10 章 -> 第一卷 -> 中期升级/扩张 -> 后期大冲突”的层级输出；若用户未指定篇幅，默认生成一版 3-5 卷的中篇/长篇大纲。
6. 若不对应，不要强行套榜单生成大纲。先提出 2-4 个关键疑问，集中询问用户是否要保留原主题、向哪个热门题材靠拢、主角推进机制是什么、爽点想落在哪类读者期待上。
7. 若用户明确表示“不需要匹配热门题材，按原设定写”，可以生成不参考榜单的大纲，但要注明这不是按热门题材榜单生成。

## 分析口径

- 题材优先使用中文网文读者熟悉的分类词，例如都市脑洞、玄幻脑洞、末世求生、历史脑洞、悬疑灵异、现言甜宠、古言宅斗、系统流、修仙、异能、经营种田、年代、无限流等。
- 不只按官方频道归类；结合书名、简介、标签和核心冲突判断真实卖点。
- 题材排名不是简单计数。榜单第 1 名应比第 20 名权重更高；单本极高热度作品可以提高题材权重，但不能凭一本书断言整个市场。
- “主要剧情主线”要回答主角从什么困境出发、靠什么机制推进、阶段目标是什么、长期矛盾是什么。
- “爽点”要具体到可复制机制，例如开局反转、信息差碾压、系统奖励、身份揭露、资源暴涨、复仇打脸、越级反杀、经营扩张、团队认可、情绪补偿、日常反差。
- 如果用户要求“分析宗教出”，按“分析并总结出”理解，输出题材、主线和爽点。

## 输出格式

默认使用中文输出，结构如下：

1. 数据来源与时间：列出访问日期、榜单链接、是否成功读取原页面、替代来源。
2. 连载中前二十榜单概览：用表格列出排名、书名、作者、简介要点、标签/题材、可见热度指标。
3. 热门题材排名：按综合热度从高到低列出题材、代表作品、样本数量、排名依据。
4. 剧情主线与爽点：每个热门题材用短段或表格总结主线、推进机制、爽点、读者期待。
5. 若用户提供剧情，追加“剧情匹配评估”：用户剧情主题材、命中的榜单题材、匹配等级、匹配证据、缺口、调整建议。
6. 若用户要求参考榜单生成大纲，追加“参考榜单大纲”：仅在匹配等级为高匹配或中匹配时输出原创大纲；若弱匹配或不匹配，输出疑问清单和可选靠拢方向。
7. 综合结论：概括当前连载榜偏好的叙事趋势和可用于创作选题的方向。

## 注意事项

- 榜单和热度会变化，回答中必须写明具体日期；不要声称结果长期有效。
- 若来源之间排名冲突，以番茄小说页面最新可见数据为准；若无法确认，说明冲突并保守分析。
- 不要大段复制小说简介；只摘取必要短语或转述。
- 不要把单本作品的特殊设定过度上升为整个市场结论。
- 参考榜单作品生成大纲时，只借鉴题材规律和商业结构，不复刻榜单作品的具体人物、世界观、关键事件、名场面、专有名词或表达。
- 对未成年人、宗教、民族、现实政治等敏感内容保持中性描述，只分析文本卖点和叙事功能。
